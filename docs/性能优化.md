# 问答延迟优化

2026-10-17，本地 248 个知识片段，模型 `gpt-6.1-sol`，向量模型 BGE-small-zh-v1.5，混合检索。

## 瓶颈与改动

原链路每个问题都重建流水线、创建事件循环，并可能串行进行规划、摘要、推理和最终生成。
绳索取心题实际检索仅 0.96 秒，5 次模型调用合计 40.87 秒，总耗时 45.18 秒。

- 增加请求级阶段计时、模型调用次数、首个答案片段时间；并行子检索传播请求上下文。
- 简单问题优先一次检索和一次最终生成；需要中间实体或推理的任务保留原流程。
- 仅在检索直接通向最终输出时省去摘要；最终输出统一生成，避免重复改写。
- 复用流水线与模型 HTTP 连接；配置变更会清空流水线缓存。未缓存答案或检索结果。
- 每个查询进程复用固定事件循环，避免异步限流器跨循环复用。两个独立进程承接问答，并发已满返回 409。
- 增加 NDJSON 流式接口：阶段进度、召回提示、答案片段、最终核验结果。中断不标记成功。

| NR826M 钻头直径 | 50.93 秒 | 13.39 秒 | 7 → 2 |
| 标准全文缺失 | 36.56 秒 | 16.26 秒 | 5 → 2 |

三题平均 44.22 → 16.18 秒，本轮减少约 63.4%。两组均通过这三题的事实规则、预期来源和引用编号检查。
首次请求包含启动时间，优化组后续请求复用运行实例；每个问题仍实际调用模型。
这是三个问题各一次的样本，受模型输出、网络和调用顺序影响，不代表稳定 SLA 或真实准确率。
另对其余五道验收题完成优化链路回归，连同上述三题共覆盖八题，均通过规则检查；自动规则不能代替人工语义评审。

流式接口另一次实测：首个进度事件 0.031 秒，首个答案片段 16.887 秒，完整答案 18.59 秒。
进度事件不是答案首字；页面分别展示检索、规划、生成耗时。

## 第二轮：跳过简单问题规划、隔离并发

120 字以内、包含领域词及明确问法，且未命中比较、计算、多问等规则的问题，直接创建检索和输出任务。
模型仍依据召回原文生成答案和引用；其他问题继续模型规划。规则路由存在误判可能，八道固定题不代表泛化质量。

| 同题单轮 | 第一轮优化 | 本轮 HTTP 总耗时 | 本轮模型调用 |
| --- | ---: | ---: | ---: |
| 绳索取心原理 | 18.88 秒 | 13.30 秒（新进程首题） | 1 |
| NR826M 钻头直径 | 13.39 秒 | 5.12 秒 | 1 |
| 标准全文缺失 | 16.26 秒 | 6.02 秒 | 1 |

本轮从 HTTP 请求发出计时，包含进程调度与流式传输；上一轮为业务函数计时，非严格同口径基准。
八道题均通过事实规则、预期来源和引用编号检查；不等同于人工语义评审。
另测“比较绳索取心与普通取心回收岩心的流程区别”，确实进入规划路径并正常完成、引用编号有效；耗时 46.78 秒、7 次模型调用。
复杂问题的多次模型调用仍是瓶颈，本轮未把复杂问题改为一次直接检索。

工作台使用两个独立查询进程，每个进程一次只执行一道题，配置、管线缓存和异步循环互不共享。
Windows 凭据刷新使用文件锁，避免两个进程同时刷新同一授权。增加进程会增加内存和模型并行调用量。
两道真实问答并发耗时 12.53 秒（单题分别 12.52、11.16 秒，其中一道包含新进程初始化），健康接口返回 200，第三题返回 409。
该结果验证基本并发能力，不代表高并发容量。自动测试覆盖配置与消息隔离、授权只刷新一次、断开后不提前释放名额。
